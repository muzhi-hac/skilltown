# Lesson UX P1 Implementation Plan

> **For agentic workers:** Execute this plan task-by-task in the current task. Steps use checkbox (`- [ ]`) syntax for tracking. No parallel delegation is required.

**Goal:** 修复六项 P1，保留自由回答，让参考资料按需阅读，输入和提交随时可达，切页与刷新可继续当前学习。

**Architecture:** 服务端 attempt 是学习状态的唯一权威；App 管理当前任务和草稿，Lesson 只展示受控状态。浏览器 sessionStorage 存同标签页的恢复指针与草稿，恢复后先向服务器核对；资料展示与作答区分离。

**Tech Stack:** 现有 React / TypeScript / Vite、FastAPI / SQLite；增加 react-markdown、remark-gfm；测试增加 Vitest、jsdom、Testing Library，并保留 Python API 测试和现有 Chrome 验收脚本。

## 0. 范围、基线和决策

- 用户确认：没有选择题，只有自由输入。默认折叠参考资料，提交按钮首屏可见。
- 本文是待执行方案；本轮没有修改应用功能。已确认上一轮基线：53 项后端测试通过、前端 build 通过、lint 6 条 warning。
- 本轮不调整题目、评分标准、推荐算法、模型预算或 NPC 薄记忆；不恢复旧 Godot 小镇路线。
- 采用 Enter 换行、Ctrl/⌘+Enter 提交；输入法组合期间任何 Enter 都不提交。
- “首屏”验收按 CSS viewport 而非物理屏幕像素；正常桌面 1280×720、1440×900，移动 390×844、360×640。浏览器 200% 缩放和移动键盘开启另外验收可达性。极短视口不靠裁切隐藏控件，允许页面滚动。

## 6. Task E：刷新恢复服务端状态（P1-4）

### E1. 后端恢复补齐

当前 GET attempt 调用 `_attempt_response`，feedback 默认 None、effect 默认 none；直接补前端 GET 会丢失回退入口。

- [ ] 先补 API 失败测试：提交有后果的回答 → GET 同 attempt → feedback、effect、assessment_status 应相同，GET 不增加证据/事件；再 hint → GET 后仍保留原反馈及 assisted；rewind → GET 不出现旧后果。
- [ ] SQLite attempts 增加可空 `presentation_json TEXT`。初始化时通过 PRAGMA table_info 检查列，旧库只执行一次 ALTER TABLE；不删除或重建表。审查所有 attempts INSERT，改为显式列名以兼容增列。
- [ ] presentation_json 只包含 `feedback`、`effect`、`assessment_status`、`learning_updates`、`feedback_mode`。respond 的已有事务内写入响应展示字段，与 revision、证据、事件一起提交；不能先提交答案再异步保存展示。
- [ ] GET 读取已保存展示字段，再以当前数据库 attempt 构造 response；当前 revision、assisted、node、timing、status 永远取数据库，不接受展示快照覆盖。
- [ ] hint 不清理最近反馈；rewind 的事务内重置 feedback/learning_updates/assessment_status，保存 rewind_available；start 新 attempt 使用默认展示字段。版本校验仍先于返回。
- [ ] 旧 attempt 的空 presentation_json 使用旧事件 response_json 只在其 attempt_id、revision 与当前状态一致时迁移展示字段；其他情况返回当前节点，并由当前节点的合法 rewind target 决定回退是否可用。不得把任意旧答案反馈挂到新节点。

### E2. 前端启动恢复

- [ ] Boot 顺序固定为 ensureSession → getTown → 读取本标签页恢复记录 → GET attempt → 校验版本/归属 → setAttempt 和角色 → 展示 Lesson。恢复成功时跳过 first-visit screening；初始化使用单次 promise/ref 防止 StrictMode 重复启动产生竞态。
