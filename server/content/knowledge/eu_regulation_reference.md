### Chunking Strategy

- **Primary unit**: Individual Article (e.g., "GDPR Art. 6 — Lawfulness of processing"). Recitals linked as supporting context.
- **Chunk enrichment**: Each chunk should carry structured metadata (see below) plus the text of directly referenced cross-articles.
- **Hierarchical linking**: Build a graph of cross-references (e.g., AI Act Art. 10 → GDPR Art. 5(1)(c) on data minimisation) so the retriever can pull related provisions.

### Metadata Schema per Chunk

```json
{
  "regulation_name": "General Data Protection Regulation",
  "regulation_citation": "Regulation (EU) 2016/679",
  "article_id": "Art. 33",
  "article_title": "Notification of a personal data breach to the supervisory authority",
  "domain": "data_protection",
  "sub_domain": "breach_notification",
  "effective_date": "2018-05-25",
  "last_amended": null,
  "instrument_type": "regulation",
  "directly_applicable": true,
  "max_penalty": "EUR 10M or 2% global turnover",
  "target_audience": ["all_employees", "DPO", "IT_security"],
  "related_articles": ["Art. 34", "Art. 4(12)"],
  "keywords": ["data breach", "72 hours", "notification", "supervisory authority"]
}
```

### Retrieval Tips

- Tag each chunk with `instrument_type` ("regulation" = directly applicable; "directive" = requires national transposition — always flag that local law may vary).
- Include `effective_date` and amendment history so the system can filter for currently-in-force provisions and flag upcoming deadlines.
- For directives, link to known national transposition acts (e.g., Germany's BDSG for GDPR, HinSchG for Whistleblowing Directive) where available, as employee training often requires the national-level detail.
- Maintain a `compliance_deadline` field for regulations with phased application (AI Act, CSRD, CRA) so the RAG can answer "what do we need to comply with by [date]?" queries.
